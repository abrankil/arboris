# Árboris — ASC Field-to-Contract Translation Adapter

Status: EXPERIMENTAL / AUDITABLE  
Version: 0.1  
Case: FIELD-ARR-2026-09-16-01  
Purpose: translate curated field/environment evidence into an ASC v0.1 contract without closing unsupported decisions.

## 1. Boundary

This adapter is upstream of ASC.

It does not execute a generative model, render an image, infer a map, identify species, or decide ecological placement.

Its job is to make the transformation from field evidence to an ASC contract explicit and auditable.

```
field package
  -> selected evidence
  -> observed facts
  -> bounded interpretation
  -> explicit OPEN items
  -> ASC v0.1 contract
  -> ASC compiler
  -> generated prompt
  -> external executor / renderer
```

The adapter must never silently convert an interpretation into an authorized fact.

| visible materiality | photographs / observed notes | transfer only what is directly visible | TRANSFER |

| generative provider | execution layer | do not infer | OPEN |

## 4. Loss / preservation matrix

### Preserved

- provenance of the field package;
- distinction between observation and interpretation;
- explicit uncertainty;
- explicit OPEN decisions;
- structural ASC constraints;
- prohibition against treating generated output as automatic evidence.

### Intentionally not promoted

- exact spatial coordinates unless recorded in source metadata;
- ecological classification beyond what the source documents;
- species identity based solely on visual resemblance;
- placement rules;
- map topology;
- gameplay geometry;
- renderer-specific implementation;
- generative provider selection.

### Information that may be transformed

Visual evidence can be transformed into bounded scene-language constraints such as:

- visible rock mass;
- relative vegetation density;
- visible vertical structure;
- exposed soil;
- foreground/background relationships;
- documented atmospheric conditions;
- documented scale references.

The transformation must retain the distinction between `observed` and `interpreted`.

## 5. ASC v0.1 output shape

The adapter produces only the fields accepted by the current ASC v0.1 compiler:

- `version`
- `executionMode`
- `testId`
- `objective`
- `authorizedSources`
- `structuralContract`
- `mandatoryRelations`
- `open`
- `doNotInfer`
- `prohibited`
- `artisticFreedom`
- `cameraFormat`
- `readingPriorities`
- `validationCriteria`

No new top-level ASC field is introduced by this adapter.

## 7. Reduction test

The adapter is considered reduced if removing any field or constraint does not change the evidentiary boundary or executable meaning.

The current candidate should therefore be tested by removing, one at a time:

1. field-package provenance;
2. observed/interpreted separation;
3. spatial OPEN constraints;
4. taxonomic OPEN constraints;
5. execution separation;
6. generated-output prohibition.

Expected result: each removal either weakens traceability or permits an inference that the current contract explicitly blocks.

Conversely, fields that merely restate information already guaranteed by ASC v0.1 should not be duplicated in the adapter.

## 8. Acceptance boundary

This artifact is accepted only as a translation specification / experiment.

It does not constitute:

- a definitive scene contract;
- a finalized environment manifest entry;
- a MAP artifact;
- a botanical placement rule;
- an approved art rule;
- an end-to-end generative implementation.

Those remain separate artifacts and require their own evidence and review.
